**14 October 2026. Decision: NO-GO for real commissions and payments.** This pass inspected and changed local code and SQL only. It made **no connection to any remote database**, ran no Supabase remote command, changed no provider settings, and performed no deployment, charge, refund, commit or push. The original released artwork collection remains visible through the catalog compatibility path until its schema is migrated.

## Remaining risks and release gates

1. **Target identity and hosted schema:** verify the exact disposable reference/branch in the Dashboard. The current default `.env.local` was identified earlier as production; it was not used for remote work. Check actual migration history, Auth dependency, grants, RLS, Storage policies/objects and private/public artwork URLs before any SQL. The historical first migrations have temporary permissive states if applied separately; a fresh project needs the guarded atomic plan, and a partially installed project needs reviewed forward patches.
2. **Owner login/recovery:** the browser currently calls Supabase `signInWithPassword` directly. Hosted Auth rate limits, signup/email confirmation, password recovery, MFA factor lifecycle, sign-out/session revocation and a secure owner recovery procedure are unverified. The removed custom recovery route was intentionally not restored because its old timing/outbox behavior was unsafe. Abandoned unverified TOTP factors may need provider cleanup. Do not claim login/recovery readiness from mocks.
3. **Money:** a capture arriving after an owner cancelled an expired order can fail the current SQL state guard and require manual reconciliation while gateway money exists. The real Razorpay test-mode matrix, callback retries, delayed/out-of-order events, capture/refund totals, and owner reconciliation have not been run. Keep checkout closed until this edge case has a reviewed resolution and sandbox evidence.
4. **Files and publishing:** local fixtures cannot test real Storage object paths, signed URLs, policy combinations, customer A/B reads or public artwork bucket inventory. Public asset URLs cannot be made private by merely unpublishing a database row. Do not place drafts in a public bucket.
5. **Operational reliability:** automatic cron expiry still writes status and audit separately. Hosted Redis fail-closed behavior, Vercel header trust, Resend delivery, notification/cleanup schedules, monitoring and backup/restore have not been exercised. A limiter outage currently returns a generic 429; operations should distinguish outage from actual abuse.
6. **Hosted gate:** local build and browser checks pass. They cannot establish real Auth, Storage object policies, provider callbacks, multi-connection concurrency, production deployment behavior or backup/restore. Physical iOS/Android and other browser engines were not run.

The runbook at `SUPABASE_REHEARSAL_RUNBOOK.md` lists every manual Dashboard checkpoint, the exact 11-file order, metadata SQL, the guarded local bundle, review/test commands and data-preserving recovery. **Do not enable real commissions or payments** until the hosted rehearsal, Storage object checks, owner MFA/account recovery and sandbox integrations pass.
